# esctest2's tests that fail against Ghostty's core (libghostty-vt, at the
# commit run.sh pins), each with its reason: read by `run.sh esctest
# --terminal ghostty` (src/esctest.rs, and the README's "esctest" section),
# as esctest-expected.txt is for fux-vt. The run fails on a failure not
# listed here, and on a test listed here that passes, so the list never goes
# stale: when Ghostty's pin moves and a test passes, remove its line.
#
# Ghostty's core answers as src/answering.rs says: its own replies, with
# its size given as its app gives it (src/engines/ghostty.rs, `answering`),
# and DECRQCRA, which it does not answer, answered from its screen. Tests
# that read cells in origin mode cannot be read (its margins are not in its
# API) and are skipped, not listed.
#
# A line is `CLASS.test_name  KIND: why`. KIND is one of:
#
#   departure:        libghostty-vt does otherwise by its design, as its
#                     source shows
#   spec:             a choice the specs leave open that esctest's
#                     expectation (xterm's) does not share
#   not-implemented:  libghostty-vt does not do it: its source has no
#                     handling for it (the file is named)
#   xterm-too:        xterm fails it as well: esctest marks it a known bug
#                     of xterm's, or needing an option xterm is not run
#                     with by default, or xterm (run.sh esctest --xterm)
#                     fails it the same way
#   bug:              a Ghostty bug: where in its source, and a replay
#
# Ghostty's parser drops DECSTR (CSI ! p), with which esctest resets the
# terminal before every test, so a test can fail from what the one before it
# left; those that pass alone (`run.sh esctest --terminal ghostty
# '^NAME$'`) say so. src/terminal/... paths are in Ghostty's source
# (~/.cache/fux-vt-compare/ghostty).
