# esctest2's tests that fail against fux-vt, each with its reason: read by
# `run.sh esctest` (src/esctest.rs, and the README's "esctest" section).
# The run fails on a failure not listed here, and on a test listed here that
# passes, so the list never goes stale: when a change makes a test pass,
# remove its line.
#
# A line is `CLASS.test_name  [SCOPE] KIND: why`. SCOPE is empty for a test
# that fails both directly and in a fux pane, `[direct]` for one that fails
# against fux-vt alone, `[fux]` for one that fails only in a pane. KIND is
# one of:
#
#   departure:        fux-vt does otherwise on purpose, as its README records
#   spec:             a choice the specs leave open, or fux's own, that
#                     esctest's expectation (xterm's) does not share
#   not-implemented:  fux-vt does not do it, and no real program needs it:
#                     the corpus (corpus/INVENTORY.md) has no program
#                     sending it, unless the line says otherwise
#   xterm-too:        xterm fails it as well: esctest marks it a known bug
#                     of xterm's, or needing an option xterm is not run
#                     with by default
#   bug:              a fux-vt (or fux) bug, to fix in a later PR, with
#                     its replay
#
# esctest runs with --expected-terminal=xterm --max-vt-level=4 (see
# src/esctest.rs). Tests needing VT level 5, and those esctest does not try
# in xterm, are skipped and not listed.
