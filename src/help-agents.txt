fux for agents: driving panes from a program. Everything is files; you need no viewer.
The lines indented by four blanks are one shell session, top to bottom: they are run as
written by tools/help-agents.sh. Names here (agent-demo, job) are examples: choose your own.

WHAT THERE IS
A pane is a directory. One small process (its holder) runs a program on a terminal of its
own and keeps the directory's files up to date. A workspace is a directory of panes. The
session directory holds the workspaces: $FUXN_DIR if set, else $XDG_RUNTIME_DIR/fux-next,
else ~/.cache/fux-next. If you run inside a pane, $FUXN_PANE is your own pane's directory,
its parent your workspace, and that one's parent the session.

START A PANE
    D=$(fux dir)                              # the session directory
    P=$(fux start agent-demo/job -- sh)       # workspace agent-demo, pane job: prints $D/agent-demo/job
    ls "$D" "$D/agent-demo"                   # workspaces; the panes of one
NAME is WORKSPACE/PANE, or WORKSPACE/ for the next free number, or PANE alone (workspace
main; typed in a pane, that pane's workspace). Letters, digits, . _ - only. No program
after -- means $SHELL. The program gets the starter's environment and working directory,
and its first size from COLUMNS and LINES (else 80x24):
    W=$(cd / && COLUMNS=120 LINES=40 fux start agent-demo/wide -- sh -c 'pwd; exec sleep 600')
A second start of a name whose pane is alive fails ("a holder already keeps this pane")
and changes nothing. A name whose program has ended is started again in place, its old
files replaced.

TYPE INTO IT
`in` is a FIFO: bytes written to it are typed to the program. Enter is \r.
    printf 'echo hello\r' > "$P/in"
    text='any text, with % and \ in it'; printf '%s' "$text" > "$P/in"; printf '\025' > "$P/in"
Keys are their bytes: Ctrl-C \003, Ctrl-D \004, Ctrl-U \025, Escape \033, Tab \t, Backspace
\177, Up Down Right Left \033[A \033[B \033[C \033[D (\033OA and so on while `modes` says
appcursor). One write of at most 512 bytes arrives whole; larger writes may mix with
another writer's, so send long text in pieces of 512 if anyone else may type there. To
paste (text with line breaks that must not run line by line) into a program whose `modes`
says paste, write \033[200~ before the text and \033[201~ after it.

READ IT
    n=0; until grep -q '^hello' "$P/screen"; do n=$((n+1)); [ $n -lt 100 ] || break; sleep 0.1; done
    cat "$P/screen"                           # the screen now, plain text, one line a row
    cat "$P/screen.styled"                    # the same with colour codes, safe to cat
    cat "$P/history"                          # lines that scrolled off the top (history.1: older)
`screen` is a frame, not a log: it is replaced up to 40 times a second, some milliseconds
after the program prints. So never read once and conclude: loop until you see what you
wait for, as above (always with a limit). One fact, one small file, a line each:
    cat "$P/size" "$P/cursor" "$P/modes" "$P/state" "$P/status"
size    COLS ROWS                 cursor  ROW COL shown|hidden SHAPE  (from 0)
modes   words: alt paste appcursor keypad focus mouseN mousesgr keysN (empty line: none)
state   running | hungup | exited CODE | killed SIGNAL
status  holder N / pid N (the program's) / command ...
top     the line number, from 0, of the screen's first row in all the pane printed
wraps   the screen rows (from 0) that continue the row above (a wrapped line)
title, cwd, clipboard, notice: what the program set last (absent until it does); log:
what the holder refused; marks, links: below and in the README. A fact can be one frame
(25 ms) ahead of a screen read just before it: trust the rows you read over `size`.
All the text so far, wrapped lines joined (history, then the screen without blank tail):
    read -r wraps < "$P/wraps"
    whole() { cat "$1/history.1" "$1/history" 2>/dev/null || :; awk -v w="$wraps" 'BEGIN { n = split(w, a, " "); for (i = 1; i <= n; i++) j[a[i] + 1] = 1 } { r[NR] = $0; if ($0 != "") last = NR } END { for (i = 1; i <= last; i++) printf "%s%s", (i > 1 && !j[i] ? "\n" : ""), r[i]; if (last) print "" }' "$1/screen"; }
    whole "$P" | tail -n 5

WAIT
For output to stop changing (a program redrew, a command went quiet), compare two reads:
    a=; b=x; n=0; until [ "$a" = "$b" ] || [ $n -ge 100 ]; do a=$b; sleep 0.3; b=$(cksum < "$P/screen.styled"); n=$((n+1)); done
For a program's end, `fux wait DIR`: it returns when the pane's holder is gone, prints
`pid N` and `state ...`, and every file of the pane is then final (do not poll `state`).

RUN A COMMAND, GET ITS OUTPUT AND EXIT CODE
Surest: make the command the pane's program. The pane stays after it ends, to be read.
    J=$(fux start agent-demo/ls -- sh -c 'ls /; exit 3')
    fux wait "$J"                             # pid N, then: state exited 3
    read -r wraps < "$J/wraps"; whole "$J"    # its output
In a shell you keep typing into, print a mark after the command that the typed line itself
does not contain (here the typed line has $? where the output has a number):
    printf 'ls /nonexistent; echo "<<t1:$?>>"\r' > "$P/in"
    n=0; until grep -q '<<t1:[0-9]*>>' "$P/screen"; do n=$((n+1)); [ $n -lt 100 ] || break; sleep 0.1; done
    grep -o '<<t1:[0-9]*>>' "$P/screen"       # <<t1:2>> : the exit code (use a new tag each time)
A shell that marks its prompts (OSC 133) needs no mark of yours: `marks` gets a line
`LINE AT KIND` for each (KIND prompt, command, output, end; `end` with the exit code):
    S=$(fux start agent-demo/marked -- env PS1='\[\e]133;A\a\]$ ' PROMPT_COMMAND='printf "\e]133;D;%s\a" "$?"' bash --norc -i)
    printf 'false\r' > "$S/in"
    n=0; until grep -q ' end 1$' "$S/marks"; do n=$((n+1)); [ $n -lt 100 ] || break; sleep 0.1; done
    grep ' end ' "$S/marks" | tail -n 1       # LINE AT end 1

FULL-SCREEN PROGRAMS (vim, less, htop)
`modes` says alt while a program is on the alternate screen; `screen` is then its screen.
Send keys as bytes, then wait for the screen to settle or to show what you expect.
    printf 'less "%s/status"\r' "$P" > "$P/in"
    n=0; until grep -q alt "$P/modes"; do n=$((n+1)); [ $n -lt 100 ] || break; sleep 0.1; done
    printf '/pid\r' > "$P/in"                 # search in less; in vim: printf '\033:wq\r'
    printf 'q' > "$P/in"
    n=0; while grep -q alt "$P/modes"; do n=$((n+1)); [ $n -lt 100 ] || break; sleep 0.1; done

RESIZE, RING, END
`ctl` is a FIFO too, one command a line:
    echo 'resize 100 30' > "$P/ctl"           # COLS ROWS, each 1 to 500
    printf 'notify %s\n' 'the build is done' > "$P/ctl"     # see "for a person" below
    echo kill > "$P/ctl"                      # hangs up the program (SIGHUP), as closing a terminal
    fux wait "$P"                             # state killed 1, or exited N if it caught the signal
`kill` does not remove the pane: its directory stays, with the last screen and state. It
does not force: a program that ignores SIGHUP lives on (`state` hungup); then signal it
yourself, e.g. kill -TERM "$(sed -n 's/^pid //p' "$W/status")". Never signal the holder.
Removing a pane's directory ends the pane as well (its holder sees it within 2 seconds).

HAZARDS
A holder killed outright (kill -9, a crash) leaves `in` and `ctl` with no reader and
`state` saying running: a write to them then waits for ever. If a pane may be dead, check
before you write (the holder lives, and `in` is still a FIFO):
    alive() { kill -0 "$(sed -n 's/^holder //p' "$1/status")" 2>/dev/null && [ -p "$1/in" ]; }
    alive "$W" && printf 'x' > "$W/in"
After a normal end the FIFOs are gone; a write then only makes a small file. Writers to
`in` wait while a program is not reading and 64 KiB are queued.

MANY PANES
Each pane is independent: start them, then wait for each.
    for i in 1 2 3; do fux start "agent-demo/w$i" -- sh -c "sleep 0.$i; echo done $i; exit $i" > /dev/null; done
    for i in 1 2 3; do fux wait "$D/agent-demo/w$i" | tail -n 1; done
    grep . "$D"/agent-demo/*/state            # every pane's state, with its name

FOR A PERSON WATCHING
A person sees a workspace with `fux view WORKSPACE` in their own terminal (C-b d leaves
it; panes run the same without it). Do not run it yourself: it needs a real terminal. It
shows each pane as a tab unless the workspace's `layout` says otherwise; edit that with
`fux layout EDIT`, naming the workspace in FUXN_WS (in a pane: that pane's workspace):
    FUXN_WS=agent-demo fux layout split row w1 beside ls    # w1 to the right of ls
    FUXN_WS=agent-demo fux layout split col w2 beside w1    # w2 below w1
    FUXN_WS=agent-demo fux layout focus ls                  # ls gets the keys
    FUXN_WS=agent-demo fux layout                           # print it: * marks the tab shown
Edits: split row|col PANE [beside PANE] · focus left|right|up|down|next|prev|PANE ·
tab next|prev|N|- · break (the focused pane to a tab of its own) · swap next|prev ·
size row|col +N|-N · rotate · arrange row|col|grid|main. A viewer sets the size of the
panes it shows to their tiles. `notify` (above) puts words in the pane's `notice`; a
viewer showing that workspace passes them to the person's terminal and marks the tab.
To reach a person from inside a pane: printf 'notify %s\n' 'done' > "$FUXN_PANE/ctl".

MANNERS AND CLEANING UP
Work in a workspace of your own (agent-TASK). Never type into, resize, kill, rearrange or
remove a pane you did not start, nor edit another workspace's layout. Before you remove,
look at what it is (`status` names the command). When done, remove what you started and
nothing else; removing the workspace ends every pane in it:
    cat "$D"/agent-demo/*/status | grep '^command'
    rm -r "$D/agent-demo"
