fux for agents: driving panes from a program. Everything is files; you need no viewer.
The lines indented by four blanks are one shell session, top to bottom: they are run as
written by tools/help-agents.sh. Names here (agent-demo, job) are examples: choose your own.

WHAT THERE IS
A pane is a directory. One small process (its holder) runs a program on a terminal of its
own and keeps the directory's files up to date. A workspace is a directory of panes. The
session directory holds the workspaces: $FUXN_DIR if set, else $XDG_RUNTIME_DIR/fux-next,
else ~/.cache/fux-next. If you run inside a pane, $FUXN_PANE is your own pane's directory,
its parent your workspace, and that one's parent the session.

START A PANE
    D=$(fux dir)                              # the session directory (made when the first pane starts)
    P=$(fux start agent-demo/job -- sh)       # workspace agent-demo, pane job: prints $D/agent-demo/job
    ls "$D" "$D/agent-demo"                   # workspaces; the panes of one
NAME is WORKSPACE/PANE (or PANE alone: workspace main; typed in a pane, that pane's
workspace). Letters, digits, . _ - only. No program after -- means $SHELL. The program
gets the starter's environment and working directory, and its first size from COLUMNS and
LINES (else 80x24):
    W=$(cd / && COLUMNS=120 LINES=40 fux start agent-demo/wide -- sh -c 'pwd; exec sleep 600')
A second start of a live pane's name fails ("a holder already keeps this pane"); the
name of a pane whose program has ended is started again in place, its files replaced.

WAIT FOR WHAT YOU EXPECT
`screen` is the screen now, as plain text: a frame, not a log, replaced up to 125 times a
second (40 while output never pauses), a millisecond or more after the program prints. So never read once and conclude, and
never sleep and hope: wait for a text, or for the frame to change, always with a limit.
    seen() { n=0; until grep -q -- "$1" "$2" 2>/dev/null; do n=$((n+1)); [ $n -lt "${3:-100}" ] || return 1; sleep 0.1; done; }
    unseen() { n=0; while grep -q -- "$1" "$2" 2>/dev/null; do n=$((n+1)); [ $n -lt "${3:-100}" ] || return 1; sleep 0.1; done; }
    frame() { cksum < "$1/screen.styled"; }
    changed() { n=0; while [ "$(frame "$1")" = "$2" ]; do n=$((n+1)); [ $n -lt "${3:-100}" ] || return 1; sleep 0.1; done; }
    settled() { a=; b=x; n=0; until [ "$a" = "$b" ]; do n=$((n+1)); [ $n -lt "${2:-100}" ] || return 1; a=$b; sleep 0.3; b=$(frame "$1"); done; }
seen REGEX FILE [LIMIT] waits until the file has a matching line, unseen until it has
none. changed DIR FRAME [LIMIT] waits until the screen is another than the one you noted
BEFORE you acted; settled DIR [LIMIT] until two reads 0.3 s apart are the same. LIMIT is
in tries (0.1 s each, 0.3 for settled), 100 if not given.
EACH RETURNS NON-ZERO WHEN ITS LIMIT RAN OUT. Check it every time (`seen X FILE || exit
1`, or run your script under `set -e`): unchecked, you go on with nothing seen.
A match must be one that was not there before you acted: an old prompt, or the line you
typed yourself, matches too. So anchor (^...$), wait for `changed` first, or print a tag
the typed line does not contain (below). Settled alone can be the old frame twice. A
row's blanks at its end are not in `screen`: a prompt "$ " is the line "$", and where the
cursor stands is in `cursor`. Waiting for a first prompt, for 50 tries at most:
    seen '[$#>]$' "$P/screen" 50
A limit counts tries, not seconds: 50 tries are 5 s and what the tries themselves take
(more on a busy machine). For a limit in time, loop on a clock as `ended` does below with
tries, or on Linux run the wait under timeout(1).

TYPE INTO IT
`in` is a FIFO: bytes written to it are typed to the program. Enter is \r.
    f=$(frame "$P"); printf 'echo hello\r' > "$P/in"; changed "$P" "$f"; seen '^hello$' "$P/screen"
    printf 'echo $((6*7))\r' > "$P/in"; seen '^42$' "$P/screen"
What you typed is in `screen` too (the terminal echoes it), so the words you typed are no
evidence that a command ran. Wait for what only the program can produce: a value it
computed (42 above, which you never typed), or a whole row of its own, anchored ^ and $.
    text='any text, with % and \ in it'; printf '%s' "$text" > "$P/in"; printf '\025' > "$P/in"
Keys are their bytes: Ctrl-C \003, Ctrl-D \004, Ctrl-U \025, Escape \033, Tab \t, Backspace
\177, arrows \033[A B C D. One write of at most 512 bytes arrives whole; larger ones may
mix with another writer's. Paste, where `modes` says paste: \033[200~ text \033[201~.
What a program does not read: a program that reads whole lines (cat, a plain `read`) gets
at most about 4,000 bytes of one line (1,000 on macOS), the rest of the line is dropped;
under a program that reads nothing at all, typed bytes are echoed and then dropped the
same way. Only a program that reads key by key and has stopped (an editor that hangs) lets
them queue, and after some hundred KiB a writer then waits. So: delivery is known only by
what the program shows; send long text as lines, or as a paste.

A WRITE THAT CANNOT HANG, AND WHETHER A PANE IS ALIVE
A plain write (`> "$P/in"`) waits for ever if the pane's holder was killed outright
(kill -9, a crash): the FIFOs stay with no reader, and `state` still says running. Opened
for reading and writing at once (`1<>`), a FIFO never makes the opener wait:
    [ -p "$P/in" ] && printf 'echo sent\r' 1<>"$P/in"; seen '^sent$' "$P/screen"
What that gives and does not: it cannot hang on a dead pane, but there the bytes are lost
without a word. (The `-p` test is because on a pane that ended normally `in` is gone, and
`1<>` would make a plain file of that name.) Under a program that has stopped reading
keys it can still wait, as said above. So when the answer matters, ask first whether the pane is
alive, and after typing wait, with a limit, for what you expect. Alive is not what `state`
says: it is the holder's process, there and not a zombie:
    alive() { s=$(ps -o state= -p "$(sed -n 's/^holder //p' "$1/status")" 2>/dev/null) && case $s in ''|Z*) false ;; esac; }
    X=$(fux start agent-demo/crash -- sleep 600); kill -9 "$(sed -n 's/^holder //p' "$X/status")"   # a crash, to show it
    seen . "$X/state"; sleep 0.2; alive "$P"; alive "$X" || echo "crash is dead, though its state says $(cat "$X/state")"
    printf 'x' 1<>"$X/in"; echo "the write to the dead pane came back"
Its one limit: long after a crash the holder's number may be another process's. Exact,
where there is flock(1) (Linux): the holder holds a lock on the pane's directory while it
lives, so `flock -n "$X" true` FAILS for a live pane and succeeds for a dead one.

READ IT
    cat "$P/screen"                           # the screen now, one line a row
    cat "$P/screen.styled"                    # the same with colour codes, safe to cat
    cat "$P/history"                          # lines that scrolled off the top (history.1: older)
    cat "$P/history.styled"                   # the same lines with colour codes (history.styled.1: older)
    cat "$P/size" "$P/cursor" "$P/modes" "$P/state" "$P/status"
One fact, one small file (absent until there is something to say, where noted):
size    COLS ROWS, e.g. `80 24`
cursor  ROW COL shown|hidden SHAPE, from 0, e.g. `2 8 shown 0`: row 2 is line 3 of screen
        (a fifth word, `#rrggbb`, if the program gave the cursor a colour; a colour a program
        sets for its pane is in `screen.styled` as direct colour: `38;2;R;G;B`, `48;2;R;G;B`
        on every cell for a background, `58:2::R:G:B` for an underline)
modes   words, or an empty line: `alt` (a full-screen program has the alternate screen),
        paste, appcursor, keypad, focus, mouseN, mousesgr, keysN
state   running | hungup | exited CODE | killed SIGNAL
status  three lines: holder N / pid N (the program's) / command ...
top     the number, from 0, of the screen's first row among all lines the pane printed
wraps   the screen rows (from 0) that continue the row above: `1 2` is one line in 3 rows
title   the window title the program set (absent until it does)
cwd     the program's directory, if it announces it (absent else): a shell must, at each
        prompt. For bash: PROMPT_COMMAND='printf "\033]7;file://%s\007" "$PWD"'
notice  `N WORDS`: N grows by one with each notice, WORDS may be none (a bell). E.g.
        `1 the build is done`. Absent until the first.
marks   `LINE AT KIND`, a line for each prompt mark of a shell that makes them (below)
links   `LINE COL LEN ADDRESS` for each link (OSC 8) on the screen, e.g. `24 0 4 https://x.y`:
        LINE counts as `top` does (screen row = LINE - top, if no row above wraps), COL is
        the first cell from 0, LEN the number of cells
log     what the holder refused or lost. (Also: clipboard, pictures and pic-N.sixel.)
A fact can be one frame (the next writing of the files) ahead of a screen read just before it. All the text of a
pane, oldest first, wrapped rows joined into the lines that were printed:
    whole() { cat "$1/history.1" "$1/history" 2>/dev/null || :; awk -v w="$(cat "$1/wraps")" 'BEGIN { n = split(w, a, " "); for (i = 1; i <= n; i++) j[a[i] + 1] = 1 } { r[NR] = $0; if ($0 != "") last = NR } END { for (i = 1; i <= last; i++) printf "%s%s", (i > 1 && !j[i] ? "\n" : ""), r[i]; if (last) print "" }' "$1/screen"; }
    whole "$P" | tail -n 5
It is exact for a pane that is still or ended, but for: colours, blanks at a line's end,
empty lines at the very end, and text older than the two history files keep (4 to 8 MiB).

RUN A COMMAND, GET ITS OUTPUT AND EXIT CODE
Surest: make the command the pane's program. `fux wait DIR` returns when the pane's holder
is gone, and every file of the pane is then final. It prints `pid N` and `state ...`: the
exit code is in that line (fux wait itself exits 0). The pane stays, to be read.
    J=$(fux start agent-demo/ls -- sh -c 'ls /; exit 3')
    code=$(fux wait "$J" | sed -n 's/^state exited //p'); echo "exit code $code"
    whole "$J"                                # all it printed
fux wait has no limit: it waits as long as the program runs. To bound it, wait for the
holder to go, with a limit, and then ask:
    ended() { n=0; while alive "$1"; do n=$((n+1)); [ $n -lt "${2:-100}" ] || return 1; sleep 0.1; done; }
    ended "$J" 50 && fux wait "$J" | tail -n 1
In a shell you keep typing into, print a tag after the command that the typed line itself
does not contain (here the typed line has $? where the output has a number):
    printf 'ls /nonexistent; echo "<<t1:$?>>"\r' > "$P/in"; seen '<<t1:[0-9]*>>' "$P/screen"
    grep -o '<<t1:[0-9]*>>' "$P/screen"       # <<t1:2>> : the exit code (use a new tag each time)
A shell that marks its prompts (OSC 133) needs no tag: each mark is a line `LINE AT KIND`
in `marks`. This bash makes three kinds: `prompt`, `command` (where typing starts) and
`end CODE` (written before each prompt, the first one too: `end 0` is there from the
start). The fourth, `output`, needs PS0='\e]133;C\a' and bash 4.4.
    S=$(fux start agent-demo/marked -- env PS1='\[\e]133;A\a\]$ \[\e]133;B\a\]' PROMPT_COMMAND='printf "\e]133;D;%s\a\e]7;file://%s\a" "$?" "$PWD"' bash --norc -i)
So never wait for "an end": wait for one MORE than there were before you typed.
    count() { grep -c " $2" "$1/marks" || :; }
    more() { n=0; while [ "$(count "$1" "$2")" -le "$3" ]; do n=$((n+1)); [ $n -lt "${4:-100}" ] || return 1; sleep 0.1; done; }
    seen ' prompt$' "$S/marks"; e=$(count "$S" end); p=$(count "$S" prompt)
    printf 'cd /; false\r' > "$S/in"; more "$S" end "$e"; more "$S" prompt "$p"       # its end, then the next prompt
    grep ' end' "$S/marks" | tail -n 1; cat "$S/cwd"       # LINE AT end 1, and /

FULL-SCREEN PROGRAMS (vim, less, htop)
`modes` says alt while one is on the alternate screen; `screen` is then its screen. Send
keys as bytes; after each, wait for a changed frame or for the text you expect.
    printf 'less "%s/status"\r' "$P" > "$P/in"; seen alt "$P/modes"
    f=$(frame "$P"); printf '/pid\r' > "$P/in"; changed "$P" "$f"      # search; vim: printf '\033:wq\r'
    printf 'q' > "$P/in"; unseen alt "$P/modes"
A program that asks what its terminal is gets fux's own answers: XTVERSION `fux-next N`;
COLORTERM=truecolor in its environment; and by name (XTGETTCAP) only what fux does: TN name
Co colors RGB Tc setrgbf setrgbb Smulx Setulc Ss Se. So Neovim uses true colour and
curly underlines with no setting, and nothing asks for what is not there.

RESIZE, RENAME, RING, END
`ctl` is a FIFO too, one command a line: resize COLS ROWS, notify WORDS, kill.
    echo 'resize 100 30' > "$P/ctl"; seen '^100 30$' "$P/size"
    printf 'notify %s\n' 'the build is done' > "$P/ctl"; seen 'build is done' "$P/notice"
    mv "$W" "$D/agent-demo/broad"; W=$D/agent-demo/broad    # a rename: the pane lives on, under the new path
    echo kill > "$P/ctl"; fux wait "$P"       # hangs up the program: state killed 1, or exited N
A renamed pane is a tab of its own in the layout again, and its program's $FUXN_PANE
still says the old name. Move only within one filesystem.
`kill` hangs up (SIGHUP), as closing a terminal does. It does not remove the pane: the
directory stays, with the last screen and state. It does not force: a program that
ignores it lives on, with `state` hungup; then signal the program (never the holder):
    T=$(fux start agent-demo/stubborn -- sh -c 'trap "" HUP; echo ready; sleep 600; echo over')
    seen ready "$T/screen"; echo kill > "$T/ctl"; seen hungup "$T/state"
    p=$(sed -n 's/^pid //p' "$T/status"); kill -TERM "$p"; fux wait "$T"    # state killed 15
`state` and `fux wait` are about the pane's program alone, not about what it started:
here the shell is gone and its `sleep` runs on. The program leads a process group of its
own number, and what it started is in it as a rule (a job-control shell's jobs are not):
    kill -0 -"$p" && echo "something of pane stubborn still runs"       # pgrep -g "$p" lists it
    kill -TERM -"$p"; sleep 0.3; kill -0 -"$p" 2>/dev/null || echo "nothing of it is left"
Removing a pane's directory ends the pane too (its holder sees it within 2 seconds).

MANY PANES
    for i in 1 2 3; do fux start "agent-demo/w$i" -- sh -c "sleep 0.$i; echo done $i; exit $i" > /dev/null; done
    for i in 1 2 3; do fux wait "$D/agent-demo/w$i" | tail -n 1; done
Every workspace and pane of the session, with its state and command:
    for q in "$D"/*/*/; do [ ! -f "$q/state" ] || echo "${q#"$D"/} $(cat "$q/state") : $(sed -n 's/^command //p' "$q/status")"; done

WHAT A PERSON SEES
`fux view WORKSPACE` draws a workspace in a terminal (C-b d leaves it). Panes run the same
without it. Left alone it draws only the panes of the tab shown, with lines between them:
no bar, no tab names. Those are on its last row only after the prefix C-b (\002), until
the next key; Escape closes them. It shows each pane as a tab unless the workspace's
`layout` file says otherwise; edit that with `fux layout EDIT`, the workspace named in
FUXN_WS (in a pane: that pane's own). Two panes above and one below, across:
    FUXN_WS=agent-demo fux layout split col w2 beside ls    # w2 below ls: do this one first
    FUXN_WS=agent-demo fux layout split row w1 beside ls    # w1 to the right of ls, above w2
    FUXN_WS=agent-demo fux layout focus ls                  # ls gets the keys
    FUXN_WS=agent-demo fux layout                           # print it: * marks the tab shown
Edits: split row|col PANE [beside PANE] · focus left|right|up|down|next|prev|PANE · tab
next|prev|N|- (and break, swap, size, rotate, arrange).
To see what a person would, run the viewer in a pane of ANOTHER workspace and read it:
    V=$(COLUMNS=100 LINES=30 fux start agent-view/v -- fux view agent-demo); seen '│' "$V/screen"
    printf 'notify %s\n' 'look here' > "$W/ctl"; seen ' broad: look here$' "$V/notice"
    printf '\002' > "$V/in"; seen ' agent-demo .* broad' "$V/screen"       # the bar: workspace, tabs
    printf '\033' > "$V/in"; unseen ' agent-demo ' "$V/screen"            # (a key right after Escape would join it)
    cat "$V/screen"; printf '\002d' > "$V/in"; fux wait "$V"       # C-b d: the viewer leaves
A viewer sets the size of the panes it shows to their tiles. A notice (`notify`, a bell)
of a pane in the workspace shown is passed on to the viewer's terminal as `PANE: WORDS`,
and its tab is marked; a viewer in a pane has that in its own pane's `notice`, as above
(`N broad: look here`; a bell is passed on as a bell, so there it is the number alone).
From inside a pane: printf 'notify %s\n' 'done' > "$FUXN_PANE/ctl".
A viewer writes in the session `keyboard` and, only if its terminal answered, `colours`
(what its terminal can do; harmless, left behind), its key scripts in $FUXN_KEYS (else
~/.config/fux-next/keys), and while it runs a FIFO `.view.PID` in the session.

IF YOU HAVE PERL (optional: nothing else on this page needs it)
The sh forms above have three risks: a write to a dead pane is lost without a word, a
write can wait under a program that stopped reading, and `alive` can be wrong long after
a crash. With
perl (Linux and macOS ship it) there are exact forms. A write that never waits and fails
at once, saying why:
    send() { perl -e 'use Fcntl; -p $ARGV[0] or die "$ARGV[0]: not a FIFO\n"; sysopen(F, $ARGV[0], O_WRONLY|O_NONBLOCK) or die "$ARGV[0]: $!\n"; local $/; defined syswrite(F, <STDIN>) or die "$ARGV[0]: $!\n"' "$1"; }
    printf 'x' | send "$W/in"; printf 'x' | send "$X/in" || echo "refused at once"
"not a FIFO", "No such file": the pane ended or is gone; "No such device or address": no
holder reads, it is dead; "Resource temporarily unavailable": alive, its queue full. And
alive by the lock the holder holds on the pane's directory, which no pid can fake:
    locked() { perl -e 'use Fcntl ":flock"; open(D, "<", $ARGV[0]) or exit 1; exit(flock(D, LOCK_SH|LOCK_NB) ? 1 : 0)' "$1"; }
    locked "$W"; locked "$X" || echo "crash holds no lock"
In python: os.open(path, os.O_WRONLY | os.O_NONBLOCK) then os.write, and fcntl.flock.

MANNERS AND CLEANING UP
Work in workspaces of your own (agent-TASK). Never type into, resize, kill, rearrange or
remove a pane you did not start, nor edit another workspace's layout. Before you remove,
look at what it is (`status` names the command). When done, remove what you started and
nothing else; removing a workspace ends every pane in it:
    cat "$D"/agent-demo/*/status | grep '^command'
    rm -r "$D/agent-demo" "$D/agent-view"
A session holds nothing else but the viewer's files named above. In a container with no
init, ended holders stay as zombies (dead, holding nothing): use docker --init.
